# 04 — 溫度演算法設計

> 個股網路溫度系統（Stock Heat）— 設計文件 4/7
> 版本：v0.1 ｜ 最後更新：2026-06-29

## 1. 目標

把「某檔個股在一段時間內的網路內容」轉換成兩個核心指標：
- **網路溫度 Heat Score**（0–100）：被討論的「熱」程度。
- **情緒分數 Sentiment**（-1 ~ +1）：偏多／偏空傾向。

並衍生 **升溫率 Heat Velocity** 用於異常偵測。

## 2. 處理管線（單篇文件）

```
RawDocument
  → clean(text)                # 去 HTML、正規化全形半形、移除雜訊
  → language_detect            # 非中文（且非英數金融詞）跳過
  → tokenize(jieba+金融詞典)    # 斷詞 + 關鍵詞
  → ticker_recognition         # 個股辨識 + 消歧 → mentions[{ticker, confidence}]
  → sentiment(text, ticker)    # 對每個被提及個股做情緒判定
  → ProcessedDocument + DocumentTickerMention[]
```

## 3. 個股辨識（Ticker Recognition）

輸入：斷詞後的文件；字典：`data/tickers.csv`（代號／正式名／別名）。

規則（依序，分數可疊加）：
1. **代號精確匹配**：出現 4 碼代號（且鄰近有「股」「個股」「代號」等上下文）→ confidence +0.6。
2. **正式名匹配**：出現公司正式名 → +0.5。
3. **別名/簡稱匹配**：命中別名 → +0.3。
4. **上下文消歧**：簡稱有歧義（如「中華」可指多檔）時，用同段落其他金融詞、產業詞做加權；無法判定則降權或捨棄。
5. **門檻**：`confidence ≥ 0.5` 才建立 mention；一篇可關聯多檔。

輸出：`DocumentTickerMention{ document_id, ticker, confidence, positions }`。

> 正確率以人工抽樣評估，目標 ≥ 90%（見 [01](01-系統概述與需求規格.md) §7）。

## 4. 情緒分析（Sentiment）

採**漸進式**策略，介面固定、實作可替換：

### 4.1 v0：詞典 + 規則（MVP）
- 金融情緒詞典：利多詞（漲停、營收創高、看好、調升目標價…）、利空詞（跌停、下修、虧損、示警…）。
- 句法調整：否定詞反轉（「不看好」）、程度副詞加權（「大幅」）。
- 分數：`sentiment = clip(Σ詞權重 / 標準化因子, -1, +1)`。

### 4.2 v1：領域模型（後續）
- 微調中文金融情緒模型（FinBERT-zh / CKIP BERT），對「個股相關句」做三分類（多/中/空）→ 映射到 -1~+1。
- 保留 v0 作為 fallback 與冷啟動。

### 4.3 標的層級情緒
一篇文章可能同時利多 A、利空 B。情緒以「**該個股相關句子**」為單位計算，再聚合到文件層級的 per-ticker 情緒。

## 5. 溫度分數（Heat Score）

對個股 `t`、時間視窗 `w`（如「今日」），先算原始熱度 `H_raw`，再正規化到 0–100。

### 5.1 原始熱度
$$
H_{raw}(t,w) = \sum_{d \in D(t,w)} \; sw(d)\cdot conf(d)\cdot decay(d)\cdot (1 + \alpha\cdot novelty(d))
$$

- `D(t,w)`：視窗內提及 `t` 的文件集合。
- `sw(d)`：來源權重（[03](03-資料來源與擷取設計.md) §1）。
- `conf(d)`：該文件對 `t` 的辨識信心。
- `decay(d)`：時間衰減 `exp(-λ·Δt)`，`Δt` 為距今小時數；`λ` 預設使半衰期 ≈ 24h。
- `novelty(d)`：是否為原創（非轉載）；轉載文以折扣計入，避免一條新聞洗榜。`α` 預設 0.5。

### 5.2 正規化到 0–100
跨個股可比性：以當日全市場 `H_raw` 分布做百分位／對數壓縮：
$$
Heat(t,w) = 100 \cdot \frac{\log(1+H_{raw}(t,w))}{\log(1+H_{raw}^{p99})}
$$
其中 `H_raw^{p99}` 為當日所有個股 `H_raw` 的 99 百分位（避免極端值壓扁分布），結果 clip 到 [0,100]。

### 5.3 情緒聚合
$$
Sent(t,w) = \frac{\sum_{d} sw(d)\cdot conf(d)\cdot decay(d)\cdot s(d,t)}{\sum_{d} sw(d)\cdot conf(d)\cdot decay(d)}
$$
即以「對溫度的貢獻」加權的平均情緒。

## 6. 升溫率與異常偵測

- **升溫率**：`Velocity(t) = (Heat_today - Heat_baseline) / (Heat_baseline + ε)`，`baseline` 取近 7 日移動平均。
- **異常**：`Velocity` 超過動態門檻（如近 30 日 Velocity 的 mean+2σ）標記為「升溫事件」，寫入 `heat_events`，供榜單「異常升溫」與後續通知使用。

## 7. 參數與可重算

| 參數 | 預設 | 說明 |
|------|------|------|
| `λ`（衰減） | ln2/24 | 半衰期 24h |
| `α`（原創加成） | 0.5 | 轉載折扣相對量 |
| 來源權重 | 見 03 | 各來源初值 |
| 辨識門檻 | 0.5 | 建立 mention 的最低信心 |
| Velocity baseline | 7d MA | 升溫率基準 |

所有參數集中於 `config/scoring.yaml`。因 raw 與 processed 分層保存，調參後可對歷史 `processed_documents` **重算** `ticker_heat_timeseries`，不需重爬。

## 8. 計算排程

- **盤中/近即時**：每 15 分鐘對「近 48h 視窗」增量更新當日溫度。
- **每日收盤後**：對當日做最終定版計算，寫入日線溫度，刷新榜單。
- **重算工具**：`scripts/recompute.py --from YYYY-MM-DD --to YYYY-MM-DD`。

## 9. 評估

- 情緒：人工標註集，回報 Macro-F1（目標 ≥ 0.75）。
- 辨識：抽樣 precision/recall。
- 溫度合理性：與成交量/波動的相關性作為觀察性指標（非最佳化目標，避免過擬合行情）。
