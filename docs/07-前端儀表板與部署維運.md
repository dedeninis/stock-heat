# 07 — 前端儀表板與部署維運

> 個股網路溫度系統（Stock Heat）— 設計文件 7/7
> 版本：v0.1 ｜ 最後更新：2026-06-29
> 前端：Next.js 14 + TypeScript + Recharts；部署：Docker Compose（MVP）→ K8s。

## 1. 前端目標

讓使用者在 30 秒內看懂「今天哪些股在升溫、情緒偏多還偏空、單一個股的溫度走勢」。

## 2. 頁面與元件

### 2.1 首頁 `/` — 升溫總覽
- **升溫榜 / 降溫榜**切換表格（rank、代號、名稱、溫度、情緒色塊、升溫率、聲量）。
- **異常升溫**卡片（來自 `heat_events`）。
- 情緒以色彩編碼：偏多（暖紅）、偏空（冷藍）、中性（灰）。

### 2.2 個股頁 `/ticker/[ticker]`
- 頂部摘要：當前溫度、情緒、近 7 日趨勢 sparkline、熱詞 tag cloud。
- **溫度時序圖**（折線）＋ 可疊加股價（後續接行情源）。
- **情緒帶狀圖**（堆疊：多/中/空比例隨時間）。
- **關聯新聞列表**：標題、來源、時間、情緒標記、外部連結（不全文轉載）。

### 2.3 搜尋
- 全域搜尋框：輸入名稱/簡稱/代號 → 跳個股頁。

### 2.4 元件清單
`RankTable`、`SentimentBadge`、`HeatLineChart`、`SentimentBandChart`、`TermCloud`、`NewsList`、`TickerSearch`。

## 3. 前端資料流

- 以 Next.js Server Components / Route Handlers 代理呼叫後端 `/api/v1/*`。
- 榜單頁 ISR（revalidate 60s）；個股頁 SSR + client 端輪詢（盤中 30s）。
- 圖表資料來自 `/tickers/{t}/timeseries`，榜單來自 `/rankings/heat`。

## 4. 部署架構

### 4.1 MVP — Docker Compose
```yaml
services:
  postgres:   # timescale/timescaledb:latest-pg16
  redis:
  api:        # uvicorn stock_heat.api.main:app
  scheduler:  # python -m stock_heat.scheduler
  worker:     # python -m stock_heat.worker
  web:        # next start
```
- `.env` 提供 `STOCKHEAT_DATABASE_URL`、`STOCKHEAT_REDIS_URL` 等。
- volume：`pgdata` 永久化。
- 啟動順序：postgres/redis healthy → api/worker/scheduler → web。

### 4.2 擴充 — Kubernetes（後續）
- `api`、`web`：Deployment（無狀態，HPA 依 CPU/QPS）。
- `worker`：Deployment 多副本（佇列分流）。
- `scheduler`：單副本（避免重複觸發；用 leader election 或 CronJob 取代）。
- Postgres：託管服務或 StatefulSet + 備份；Redis：託管或 sentinel。

## 5. CI/CD

- **CI**（GitHub Actions）：lint（ruff）→ type（mypy）→ test（pytest）→ build image。
- **CD**：main 合併 → build/push image → 部署（compose pull / kubectl rollout）。
- 工作流檔：`.github/workflows/ci.yml`。

## 6. 觀測性

| 面向 | 工具 | 指標 |
|------|------|------|
| 指標 | Prometheus | 抓取量、佇列長度、處理延遲、API QPS/延遲、各來源錯誤率 |
| 儀表板 | Grafana | 來源健康度、每日入庫量、溫度計算耗時 |
| 日誌 | structlog → stdout → 收集 | 結構化 JSON |
| 告警 | Alertmanager | 來源連續失敗、佇列積壓、API 5xx 升高 |

## 7. 維運手冊（Runbook 摘要）

| 狀況 | 排查 |
|------|------|
| 某來源無新資料 | 查 `collector_runs`、`sources.last_success_at`；多半為改版→更新 parser selector 或啟用 fallback |
| 佇列積壓 | 擴 worker 副本；查處理層是否卡在某步（NER/情緒模型） |
| 溫度看起來怪 | 跑 `scripts/recompute.py` 重算；檢查 `scoring.yaml` 參數與當日 p99 |
| 個股誤關聯 | 更新 `data/tickers.csv` 別名 / 調高辨識門檻 |

## 8. 環境與秘密管理

- 所有秘密走環境變數 / Secret Manager，**不入 repo**（見 `.gitignore`）。
- 三套環境：local（compose）、staging、production。
