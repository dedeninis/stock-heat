# 03 — 資料來源與擷取設計

> 個股網路溫度系統（Stock Heat）— 設計文件 3/7
> 版本：v0.1 ｜ 最後更新：2026-06-29
> 本文件定義資料來源、擷取器（Collector）介面與**財經新聞模組**規格，是新聞模組實作的依據。

## 1. 資料來源總覽

| 來源類型 | 範例來源 | 取得方式 | 預設頻率 | 來源權重 | 階段 |
|----------|----------|----------|----------|----------|------|
| 財經新聞 | 鉅亨網、經濟日報、工商時報、中央社財經、Yahoo 財經 | RSS + 文章頁 HTML | 5 分鐘 | 1.0 | MVP（首要） |
| 論壇 | PTT Stock 板 | 看板列表 + 文章頁 | 10 分鐘 | 0.7 | MVP |
| 財經社群 | CMoney/Mobile01 投資版 | HTML/列表 | 30 分鐘 | 0.6 | P1 |
| 搜尋趨勢 | Google Trends | pytrends | 6 小時 | 0.5 | P1 |
| 社群平台 | X / Threads / Dcard | API/HTML | 視來源 | 0.4 | P2 |

> 來源權重為「溫度公式」中的 `source_weight` 初始值，可於 [04](04-溫度演算法設計.md) 調整。

## 2. 擷取通用原則

- **遵守 robots.txt 與 rate limit**：每來源設定最小請求間隔與每分鐘上限。
- **User-Agent 標示**：使用可識別的 UA，附聯絡資訊。
- **只抓必要欄位**：標題、內文、發布時間、URL、作者/來源名稱。
- **增量抓取**：以 URL/文章 id 做 seen-set（Redis Set + DB 唯一鍵）避免重複抓取。
- **失敗重試**：指數退避，最多 3 次；連續失敗觸發來源健康度告警。
- **時區一致**：所有時間統一存 UTC，呈現時轉 `Asia/Taipei`。

## 3. Collector 介面（plugin 化）

所有擷取器實作同一抽象介面，核心邏輯與來源解耦：

```python
class RawDocument(BaseModel):
    source: str            # 來源代號，如 "news.cnyes"
    source_type: str       # "news" | "forum" | "trends" | "social"
    external_id: str       # 來源內唯一 id（通常為正規化 URL）
    url: str
    title: str
    content: str           # 純文字內文
    author: str | None
    published_at: datetime # UTC
    raw_meta: dict         # 來源特有欄位

class BaseCollector(ABC):
    source: str
    source_type: str
    default_interval: int  # 秒

    @abstractmethod
    def discover(self) -> list[str]:
        """回傳本輪要抓的文章 URL（已過濾 seen）。"""

    @abstractmethod
    def fetch(self, url: str) -> RawDocument:
        """抓取單篇並解析為 RawDocument。"""

    def run(self) -> Iterator[RawDocument]:
        for url in self.discover():
            try:
                yield self.fetch(url)
            except Exception as e:
                self._record_failure(url, e)
```

註冊機制：`collectors/registry.py` 以 `source` 為 key 收集所有 Collector，排程器依 `config/sources.yaml` 啟用。

## 4. 財經新聞模組（News Module）詳細規格 ★

> 這是 MVP 第一個落地模組，對應程式 `stock_heat/collectors/news/`。

### 4.1 模組職責
1. 從多個新聞來源的 **RSS / 列表頁**取得最新文章 URL。
2. 過濾已抓取過的 URL（seen-set）。
3. 抓取文章頁，解析出標題、內文、發布時間、來源。
4. 產生 `RawDocument(source_type="news")` 並推入佇列（或於 MVP 直接回傳給 pipeline）。

### 4.2 來源設定（`config/sources.yaml` 範例）
```yaml
news:
  - id: news.cnyes          # 鉅亨網
    name: 鉅亨網
    rss: https://news.cnyes.com/rss/v1/news/category/tw_stock
    article_selector: "div._1R5x"   # 內文容器（示意）
    weight: 1.0
    interval: 300
  - id: news.udn            # 經濟日報
    name: 經濟日報
    list_url: https://money.udn.com/money/cate/5590
    weight: 1.0
    interval: 300
  - id: news.cna            # 中央社財經
    name: 中央社
    rss: https://feeds.cna.com.tw/cna_money.aspx
    weight: 0.9
    interval: 600
```
> 選擇器與 RSS URL 在實作時需以實際頁面驗證；設計上以「可設定」為原則，避免寫死。

### 4.3 解析流程
```
discover():
  for each configured news source:
    if source.rss:  entries = parse_rss(source.rss)
    else:           entries = parse_list_page(source.list_url)
    urls = [normalize_url(e.link) for e in entries]
    return [u for u in urls if not seen(u)]

fetch(url):
  html = http_get(url)            # httpx, timeout=10s, retry
  doc  = extract(html, source)    # 標題/內文/時間/作者
  return RawDocument(...)
```

### 4.4 內文擷取策略（穩健性）
- **首選**：來源專屬 CSS selector（精準）。
- **退場**：通用內文抽取（如 readability/trafilatura 邏輯）作 fallback，避免單一來源改版即斷料。
- 解析失敗時：仍保留標題與 meta，標記 `content_quality="partial"`，不丟棄。

### 4.5 去重
- **URL 正規化**：去 query 追蹤參數（utm_*）、統一 scheme/host。
- **內容近似去重**：對 `title+content` 算 SimHash，64-bit；漢明距離 ≤ 3 視為重複（同一新聞被多家轉載時保留來源權重最高者，其餘記為轉載計數）。

### 4.6 與個股關聯（交由處理層）
News 模組本身**不做**個股辨識，只負責產出乾淨 `RawDocument`。個股辨識在處理層統一處理（見 [04](04-溫度演算法設計.md) §3），以利所有來源共用同一套辨識邏輯。

### 4.7 輸出與錯誤處理
- 成功：`RawDocument` → `ingest.raw`（或 MVP 直接寫 `raw_documents`）。
- 抓取失敗：記錄到 `collector_runs`（來源、url、錯誤、時間），更新健康度指標。
- 指標：`news_fetch_total`、`news_fetch_error_total`、`news_fetch_latency_seconds`、`news_new_docs_total`。

### 4.8 排程
- 預設每來源 5 分鐘；可由 `interval` 覆寫。
- 單次執行設總量上限（如每來源每輪最多 50 篇）避免突刺。

## 5. 股票字典與別名

擷取/處理共用一份 `data/tickers.csv`（代號、正式名、常見簡稱、產業）。
範例：
```
ticker,name,aliases,industry
2330,台積電,"台積,TSMC,台積電",半導體
2317,鴻海,"鴻海,Foxconn,富士康",電子組裝

```

## 6. 合規與健康度

- 每來源維護 `enabled`、`last_success_at`、`error_rate`；連續失敗 N 次自動停用並告警。
- 對外 API 只輸出聚合溫度與來源連結，不全文轉載。
