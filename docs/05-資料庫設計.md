# 05 — 資料庫設計

> 個股網路溫度系統（Stock Heat）— 設計文件 5/7
> 版本：v0.1 ｜ 最後更新：2026-06-29
> 主資料庫：PostgreSQL 16 + TimescaleDB；快取/佇列：Redis。

## 1. 設計原則

- **Raw / Processed / Derived 三層分離**，支援演算法重算（[04](04-溫度演算法設計.md) §7）。
- 時序資料（溫度時間序列）使用 **TimescaleDB hypertable**。
- 時間一律存 `timestamptz`（UTC）。
- 主鍵以 `bigint identity`；外部資料用唯一鍵防重。

## 2. ER 概觀

```
tickers ───< document_ticker_mentions >─── processed_documents ──1:1── raw_documents
   │                                                  
   ├───< ticker_heat_timeseries
   └───< heat_events

sources ──< collector_runs
```

## 3. 資料表定義

### 3.1 `sources` — 來源主檔
| 欄位 | 型別 | 說明 |
|------|------|------|
| id | text PK | 來源代號，如 `news.cnyes` |
| name | text | 顯示名稱 |
| source_type | text | news/forum/trends/social |
| weight | numeric(3,2) | 來源權重 |
| enabled | bool | 是否啟用 |
| interval_sec | int | 抓取頻率 |
| last_success_at | timestamptz | 最近成功時間 |
| error_rate | numeric | 近窗錯誤率 |

### 3.2 `raw_documents` — 原始文件（Raw 層）
| 欄位 | 型別 | 說明 |
|------|------|------|
| id | bigint PK | |
| source | text FK→sources.id | |
| source_type | text | |
| external_id | text | 來源內唯一 id（正規化 URL） |
| url | text | |
| title | text | |
| content | text | 純文字內文 |
| author | text null | |
| published_at | timestamptz | 來源發布時間 |

唯一鍵：`UNIQUE(source, external_id)`。索引：`(published_at)`、`(simhash)`。

### 3.5 `document_ticker_mentions` — 文件×個股關聯
| 欄位 | 型別 | 說明 |
|------|------|------|
| id | bigint PK | |
| processed_id | bigint FK→processed_documents.id | |

唯一鍵：`UNIQUE(processed_id, ticker)`。索引：`(ticker)`、`(ticker, confidence)`。

### 3.6 `ticker_heat_timeseries` — 溫度時序（Derived 層, hypertable）
| 欄位 | 型別 | 說明 |
|------|------|------|
| ticker | text FK→tickers.ticker | |
| ts | timestamptz | 視窗時間點（日線取當日 00:00 TPE→UTC） |
| granularity | text | `daily`/`intraday` |
| volume | int | 去重後聲量 |
| heat_score | numeric(5,2) | 0–100 |
| sentiment | numeric(4,3) | -1~1 |

| source_breakdown | jsonb | 各來源貢獻 |
| scoring_version | text | 演算法版本 |

主鍵：`(ticker, ts, granularity)`。`SELECT create_hypertable('ticker_heat_timeseries','ts')`。
連續聚合（continuous aggregate）可建日榜物化視圖。

## 4. Redis 用途

| Key 樣式 | 用途 | TTL |
|----------|------|-----|
| `seen:url:{sha1}` | 已抓取 URL set/bit | 7d |
| `queue:ingest.raw` | 原始文件佇列（Stream） | - |
| `cache:rank:heat:{date}` | 升溫榜快取 | 15m |
| `cache:ticker:{ticker}:summary` | 個股摘要快取 | 5m |

## 5. 保存策略（Retention）

- `raw_documents.content`：保存 180 天後可轉冷儲存／截斷（保留標題與 meta）。
- `ticker_heat_timeseries`：長期保存（時序，量小）。
- 個資/版權：僅內部計算用途，對外不全文揭露。

## 6. Migration

使用 Alembic；初版 migration 建立上述表與 hypertable。種子資料：`tickers`（由 `data/tickers.csv` 匯入）、`sources`（由 `config/sources.yaml` 匯入）。
